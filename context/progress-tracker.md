## Decisions implemented

| Decision | Implementation consequence |
|---|---|
| Ink-Rider is discovery-and-demand first | Feeds, questions, recommendations, and reader–writer loops are primary modules |
| Primary articles remain free | Membership gates experiences, not published article bodies |
| Modular monolith | React client + Express API + MongoDB, with provider adapters kept replaceable |
| Explainable deterministic ranking first | Recommendation inputs and reasons are inspectable; no opaque ML dependency |
| Platform membership differs from creator support | Membership owns entitlements; support allocations are separate records |
| AI never silently rewrites drafts | Suggestions require explicit insertion as a new editor block |
| Moderation decisions are append-only | Reviews and competition operations create auditable records |
| Everyone can read, write, ask, vote, and participate | No progressive-role system is planned for the current product direction |
| Questions are independent from stories | Questions use their own feed, answers, votes, follows, reports, and moderation; no story attachment is part of the product model |
| Responsive web is the current platform | Phone and desktop share core capabilities; native-only features are deferred |
| Google sign-in is sign-in/sign-up only | Verified new Google users can onboard; existing password accounts are never auto-linked |
| Reader-first community before monetization | Discovery, discussion, publishing, and competitions are hardened before membership and creator-support expansion |
| Moderation enforcement is bounded and appealable | Moderators may temporarily unpublish content for 72 hours or suspend accounts for 7 days; administrators may extend content unpublication or suspend accounts for 30 days; indefinite account suspension requires platform-owner authorization, and all actions require independent appeals and append-only audits |
